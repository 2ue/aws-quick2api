# Claude Code 工具与 MCP 兼容性

2026-11-23 使用 Claude Code 2.1.280 做独立配置测试。修复了确定的协议问题，但完整工具清单下的自动调用仍有模型行为限制。

## 已复现并修复

- Claude Code 内置 Bash、Read、ToolSearch 使用 JSON Schema draft/2020-12。默认 Ajv draft-07 无法编译，首个请求返回 400。现在根据声明选择 draft-07、2019-09 或 2020-12 校验器，保留各版本约束与外部引用限制。
- Claude Code 可把环境和延迟工具目录放在消息数组的 system 消息中。现在合并进系统上下文，避免当作用户对话。
- ToolSearch 返回的 tool_reference 以前被 400 拒绝。现在保留已加载工具名称，并把对应 deferred schema 加入可调用清单；缺少 schema 仍明确报错。
- 模型曾在 Quick 云端工作区搜索本地文件，随后错误地回答目录为空。桥接指令及每轮提示现在明确区分客户端工作区与 Quick 云端工作区，并要求用客户端 runner 调用文件、命令和 MCP 工具。
- 同一账号的不同线程以前共用 workingSessionId。现在按客户端、账号与上游线程派生独立标识，同一暖线程保持连续性。
- 工具参数校验失败以前被按 502 连接故障处理，导致整个账号进入冷却。现在不因 invalid_tool_call 冷却健康账号，错误消息说明具体参数约束。

47 项回归测试、类型检查与仓库 preflight 通过。参数冷却修复由回归测试覆盖。思考模式与显示开关见[账号池说明](account-pool.md)。线上版本与最后状态以部署目录的诊断记录为准。

这些是有限样本，不能用作成功率或不存在串台的证明。并发标记测试覆盖独立会话的多轮回复；未覆盖所有客户端恢复、分支、错误会话 ID 或长期负载组合。

## 使用建议

- 文件与命令任务确认出现客户端 tool_use 和真实 tool_result。模型只说“目录为空”而没有客户端工具结果时，不能据此判断本地文件状态。
- 工具较多的编码任务优先尝试 Opus；本次两个完整任务通过。Sonnet 可以完成较少工具的任务，完整目录仍有失败样本；开启思考不保证修复。
- MCP 连接和执行由客户端完成，代理处理工具定义与结果。Quick 自身的连接器列表不代表客户端 MCP 是否可用。
- 保持稳定且独立的会话 ID；不同聊天窗口不要复用同一个显式 ID。请求完整历史仍用于一致性校验。
- 该桥接依赖模型输出结构化文本，不等同于原生 Anthropic 工具调用能力，不能保证所有 Claude Code 工具与 MCP 服务器兼容。

## 隔离测试方式

测试使用独立 CLAUDE_CONFIG_DIR、空 setting-sources、strict-mcp-config 和临时 MCP 服务。不写个人 settings、认证或 MCP 配置，不连接个人 MCP。比较测试前后个人配置文件哈希；诊断脚本、日志和样例文件放在仓库外的测试输出目录。

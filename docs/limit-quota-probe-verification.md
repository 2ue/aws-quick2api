# 限额触发用量查询验收

日期：2026-11-25。实现提交：`51bd24e`。范围：推理遇到临时限流或明确额度耗尽后，后台查询受影响账号用量并修正调度状态。

## 并发和状态约束

- 当前请求先执行既有冷却与换号，查询不占推理租约，不等待查询完成。
- 同账号在途查询合并，查询结束后60秒内不重复，失败也节流。
- 全局最多2个自动查询、100个等待、每个查询10秒超时；超时取消HTTP，关闭服务取消在途和等待任务。
- 只调用用量接口，不读取身份或云端历史，不强制刷新OAuth。已有OAuth令牌刷新仍复用原有并发合并机制。
- 查询有余量或字段不明时保留实际限流冷却；确认session/月度耗尽才修正状态。恢复时间不会缩短已有更长冷却。
- 账号对象和版本阻止迟到结果覆盖手动启停/解封、认证失败、更新的额度同步/明确额度错误、凭据替换及删除重建。
- 无启动和定时全账号轮询。运行统计通过 `runtime.quotaProbe` 暴露。
- OAuth、Web Cookie、带AWS Quick host的导入token直接访问账号对应接口；本机Outpost或缺host的token自动查询不可用时保留冷却，不切换共享授权。87账号均为OAuth。

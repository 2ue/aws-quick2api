# 混合任务与调度验收（2026-11-25）

测试目标：自然语言描述需求，由模型决定是否直接回答、读取资料、写文件或修改代码；同时验证 quota-aware 账号分配、并发上限、排队、粘性和会话隔离。没有在任务里点名工具，没有使用强制 tool_choice。模型和协议由测试指定，账号由服务调度；本项目不按任务语义自动改选模型。

## 首轮生产结果

- 14 个任务场景、24 个并发双轮会话，共 38 个场景，自动交付检查 33 通过、5 失败。另有两项真实 Claude Code 测试。
- 代码：番茄钟、Markdown 笔记、折扣为零修复、CSV 汇总；按工具结果和磁盘检查交付。独立执行折扣用例，保留无关文件。
- 文案：首屏、旧书交换活动、客户邮件、读取简报写 Markdown、两轮改价、翻译。普通文案不写文件；要求留稿时读取资料并落盘。
- 分析：读取已有代码解释数据流、直接数字分析、仅讨论架构、仅展示函数。
- 5 个失败都是账号耗尽返回 HTTP 200 + 正文 `You've reached your usage limit. Check your profile for details.`。日志误记为 success，粘性继续绑定耗尽账号。涉及账号槽 d31c7ca9b3、0d3e332436。
- 观测到总活跃请求 20、排队 6；20 个账号承担本批请求，单账号最高在途 2，未超过配置。24 个双轮会话中 20 个完成，4 个被额度提示阻断；完成会话未出现其他会话随机标记。

## 额度提示修复

参考 kuk 最新版中的精确额度提示识别，添加 QuotaReplyGuard。只在整段输出是已知额度提示且没有真实思考/工具输出时，把伪成功转成 quota_exhausted，让现有账号熔断、粘性驱逐和同模型切换流程处理。候选文本与合成路由信息在判定前缓冲，避免已交付标记阻止切换。正常引用或解释该错误不当作额度耗尽；已输出真实内容后不重新执行；所有账号耗尽返回错误。

新增测试覆盖 1 字符到整段分片、弯引号、空白、正常引用、真实思考、切换账号及粘性释放、全部耗尽和部分输出。58 项回归及 preflight 通过。本机候选重复 14 类任务全部完成，并真实隔离了一个返回伪成功提示的账号。

## 真实 CLI 和独立验证

Opus 根据目录里的开销 CSV 自行 Bash/Read，创建 Python 工具、README 和测试，执行验证；中间 Edit 失败后检查文件再继续。独立运行 5 项 unittest 全部通过，样例分类 40/30/10，总计 80。Sonnet 拟邮件直接回答，无工具调用。独立 CLAUDE_CONFIG_DIR、空 setting-sources、strict-mcp-config，个人关键配置文件前后哈希一致。

## 内容质量边界

自动交付检查通过不等于文案逐条满足要求。人工复核首轮样本发现：首屏补充了未提供的“联网自动同步/负责人”等细节；客户邮件拟入未提供的具体修复日期和同步日期；120 字以内的招募文案首稿约 130 字，且自报“约110字”，后续改稿为112字符。模型写作仍需事实和长度复核，这些样本不算严格文案约束全部通过。翻译占位符与销售数字计算正确。

网页检查覆盖文件落盘与脚本语法，没有使用浏览器验证交互或视觉。报告不宣称生产长期成功率，也不证明所有并发组合无串台。
